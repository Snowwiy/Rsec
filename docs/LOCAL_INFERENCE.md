# Local inference and export

Transformers loads only existing local paths with Safetensors and no remote model code. It can attach a local PEFT adapter. This unquantized path may exceed a 12 GB GPU for a 7B model; use a physically validated quantized GGUF runtime where appropriate. Sampling, context, token limits, system prompt and measured latency/throughput are configurable. The response envelope is JSON, but a model's answer is not guaranteed to conform to a domain schema.

llama-cpp-python is an optional binding installed separately for a reviewed llama.cpp release. It reads the model's GGUF metadata/template. `--tensor-split` and `--gpu-layers` control compatible multi-GPU builds; no CUDA build is assumed. Ollama uses a fixed loopback endpoint, no proxy and no pull endpoint. Install a local model first; cloud-tagged model names are rejected. The local Ollama service remains an operator trust boundary and should run without cloud access when strict offline operation is required.

Exports refuse an existing output directory and leave partial failed exports for inspection rather than pretending success. Adapter export requires valid Safetensors plus tokenizer metadata. Merge loads an unquantized local base and safely merges PEFT weights. Conservative RAM/storage guards can reject a theoretically possible export; use a better-resourced machine rather than disabling integrity checks. GGUF conversion invokes only an explicitly supplied clean, versioned local converter checkout. Review native/Python toolchain dependencies separately.

The GGUF Modelfile contains FROM ./rsec-Q4_K_M.gguf and local parameters. No generic TEMPLATE is injected; the GGUF must preserve a recognized official chat template. Run `ollama create rsec -f exports/gguf-v1/Modelfile` and then `ollama run rsec` after validating the exported artifact. Hash and size manifests are not semantic output validation. Test the actual exported model and compare it with its base/adapter before publishing weights.
